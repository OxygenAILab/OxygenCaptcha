# 安全边界

OxygenChallenge 的目标是组合低成本风险信号和交互证据，而不是宣称能证明“绝对是真人”。

## 同色诱饵

反色题在背景色 `B` 的容器中放置六位诱饵文本，CSS `color` 与背景完全相同。上层
SVG 只包含正确数字的反色路径，不含 `<text>`，因此：

- 正常视觉用户看到 SVG 中的正确数字。
- DOM、WebFetch、纯文本抓取器更容易拿到诱饵。
- 提交诱饵时，服务端记录 `challenge.honeypot` 强风险事件。
- 客户端仍只收到普通 `INVALID_ANSWER`，不暴露检测规则。

该设计主要对抗读取文本 DOM 的 Agent，不应被描述成完整的视觉模型防护。

## 十五类挑战的作用

| 类型 | 主要证据 | 已知边界 |
|---|---|---|
| 反色遮挡 | DOM 语义差异、视觉读取 | 截图视觉模型可解 |
| 图标网格 | 目标识别、精确多选 | 视觉模型可解，但可制造选择组合 |
| 动态覆盖 | 时间一致性、空间定位、指针交互 | seed 和轨迹公式在客户端可见，脚本仍可模拟 |
| 声音序列 | 听觉理解、顺序记忆 | 可录音转写或程序化解码 |
| 计算挑战 | 高人工时间成本、错误率 | 机器最容易计算，不能单独作为人类证明 |
| 键盘与指针 | 双输入并发、持续时间、拖动距离 | 客户端证据可伪造，需和浏览器完整性信号联动 |
| 序列记忆 | 跨阶段顺序记忆、延迟复述 | seed 规则可被脚本复现 |
| 瞬时计数 | 短时视觉编码、小规模计数 | 客户端仍可通过 seed 推导数量 |
| 股市买卖 | 低高点判断、时序与点击定位 | 完整曲线可被程序化分析 |
| 基础确认 | 长停留、复选框和浏览器上下文 | 脚本可伪造点击，只是低成本信号 |
| 方向校准 | 空间旋转与滑杆操作 | 目标角度可由 JS 直接设置 |
| 语义选择 | 常识/语义理解与选择 | 文本模型容易解答 |
| Cloudflare Turnstile | Cloudflare 托管完整性与风控 | 依赖第三方可用性和站点配置 |
| 手部动作 | 多帧骨骼动作、保持时长、摄像头上下文 | 可用录制视频或合成视频重放 |
| 朗读声学 | 同一字词多遍非严格一致性、设备端特征 | 可用高保真 TTS/录音回放攻击，需与内容绑定加强 |

动态题和计算题不应成为唯一防线。高风险场景应叠加被动浏览器完整性、网络信誉、设备轮换、
行为频率和业务侧风险，而不是无限增加可见题数量。

## 服务端保护

- Challenge ID 使用 144 bit 随机值。
- Challenge 默认 300 秒过期，最多 3 次尝试。
- 网格正确索引、声音答案、计算结果和反色正确数字只保存在服务端。
- 序列顺序、圆点数量、市场极值只保存在服务端；响应只下发种子与算法参数。
- 资源接口使用 `no-store`，Challenge 消费后立即失效。
- `siteverify` 使用 Ed25519 签名令牌，默认 120 秒有效，并以 jti 原子消费。
- 站点 secret 使用恒定时间比较。
- Origin/Referer 白名单在创建 Challenge 和嵌入页两处检查。
- Helmet 设置 CSP；Widget 资源允许跨域，但 Challenge 与嵌入页禁止缓存。
- API 默认限速；公网还应在反向代理层增加 IP、账户和路由级限速。
- 风险会话使用 3/4/6/8 步链路；中间步骤不签发令牌，会话 ID 和当前步骤绑定。
- 任一步骤尝试耗尽或诱饵命中时，整个会话立即失效。
- 自动风险评分综合 UA、Client Hints、平台/系统、语言、Cloudflare 国家、请求频次和
  UA 轮换；显式 `risk` 只能提高等级，不能把自动风险降级。
- Cloudflare Turnstile 的 siteverify 失败会关闭验证，错误码只写服务日志。
- 开放平台 secret 使用 AES-256-GCM 加密落盘；OxygenAccount OIDC 使用 Authorization
  Code + PKCE、HttpOnly 会话和 CSRF 校验。

## 当前不能防住

- 会截图并使用视觉模型的 Agent。
- 能执行 Canvas/SVG 并做视觉定位的 GUI Agent。
- 能合成完整键盘与指针事件流的自动化程序。
- 真人代答、人机协作和被盗会话。
- 能读取服务端状态或持有站点 secret 的攻击者。

## 隐私

- 不保存原始按键流、鼠标轨迹、麦克风音频或摄像头视频。
- 动态题只把最终采样点提交给服务端；键盘题只提交持续时间和距离。
- 市场题只提交买卖索引；序列题只提交选择序列；计数题只提交最终数字。
- 声音由服务端程序合成，不包含第三方录音。
- 手部动作与朗读题只在用户主动点击后请求麦克风和摄像头权限；拒绝权限时提供无障碍替代。
- 仅保存 Challenge 状态、结果、风险事件和短期令牌消费状态。
- 当前存储为单进程内存；进程重启会让未完成 Challenge 失效。
- 当前会话最多 5 分钟，完成过程中每个步骤共享同一过期时间。

## 媒体题后续门槛

手部和朗读题已经落到 alpha.6 生产实现，仍需在生产风险策略中继续加强：

1. 说话内容与随机 challenge phrase 的强制绑定，而不只做音高/频段一致性比较。
2. 摄像头深度的真实立体性检测、时序随机化、重放与录制视频识别。
3. 设备指纹、nonce、时间窗和服务端随机挑战绑定。
4. 不同地区、设备、口音、残障用户和低带宽环境的误伤率评估。
5. 权限说明、撤回路径、数据保留策略和未成年人保护。
