# 安全边界

OxygenChallenge 的目标是组合低成本风险信号和交互证据，而不是宣称能证明“绝对是真人”。

## 同色诱饵

反色题在背景色 `B` 的容器中放置六位诱饵文本，CSS `color` 与背景完全相同。上层
SVG 只包含正确数字的反色路径，不含 `<text>`，因此：

- 正常视觉用户看到 SVG 中的正确数字。
- DOM、WebFetch、纯文本抓取器更容易拿到诱饵。
- 提交诱饵时，服务端记录 `challenge.honeypot` 强风险事件。
- 客户端仍只收到普通 `INVALID_ANSWER`，不暴露检测规则。

该设计主要对抗读取文本 DOM 的 Agent，不应被描述成完整的视觉模型防护。

## 六类挑战的作用

| 类型 | 主要证据 | 已知边界 |
|---|---|---|
| 反色遮挡 | DOM 语义差异、视觉读取 | 截图视觉模型可解 |
| 图标网格 | 目标识别、精确多选 | 视觉模型可解，但可制造选择组合 |
| 动态覆盖 | 时间一致性、空间定位、指针交互 | seed 和轨迹公式在客户端可见，脚本仍可模拟 |
| 声音序列 | 听觉理解、顺序记忆 | 可录音转写或程序化解码 |
| 计算挑战 | 高人工时间成本、错误率 | 机器最容易计算，不能单独作为人类证明 |
| 键盘与指针 | 双输入并发、持续时间、拖动距离 | 客户端证据可伪造，需和浏览器完整性信号联动 |

动态题和计算题不应成为唯一防线。高风险场景应叠加被动浏览器完整性、网络信誉、设备轮换、
行为频率和业务侧风险，而不是无限增加可见题数量。

## 服务端保护

- Challenge ID 使用 144 bit 随机值。
- Challenge 默认 300 秒过期，最多 3 次尝试。
- 网格正确索引、声音答案、计算结果和反色正确数字只保存在服务端。
- 资源接口使用 `no-store`，Challenge 消费后立即失效。
- `siteverify` 使用 Ed25519 签名令牌，默认 120 秒有效，并以 jti 原子消费。
- 站点 secret 使用恒定时间比较。
- Origin/Referer 白名单在创建 Challenge 和嵌入页两处检查。
- Helmet 设置 CSP；Widget 资源允许跨域，但 Challenge 与嵌入页禁止缓存。
- API 默认限速；公网还应在反向代理层增加 IP、账户和路由级限速。

## 当前不能防住

- 会截图并使用视觉模型的 Agent。
- 能执行 Canvas/SVG 并做视觉定位的 GUI Agent。
- 能合成完整键盘与指针事件流的自动化程序。
- 真人代答、人机协作和被盗会话。
- 能读取服务端状态或持有站点 secret 的攻击者。

## 隐私

- 不保存原始按键流、鼠标轨迹、麦克风音频或摄像头视频。
- 动态题只把最终采样点提交给服务端；键盘题只提交持续时间和距离。
- 声音由服务端程序合成，不包含第三方录音。
- 当前版本不请求麦克风和摄像头权限。
- 仅保存 Challenge 状态、结果、风险事件和短期令牌消费状态。
- 当前存储为单进程内存；进程重启会让未完成 Challenge 失效。

## 后续高风险能力

麦克风说话测试和摄像头动态手势必须新增以下门槛后才能进入生产：

1. 明确的用途说明、逐项权限请求和撤回路径。
2. 端侧特征提取或短时内存处理，避免默认上传原始媒体。
3. 防重放 nonce、时间窗和设备绑定。
4. 说话内容与随机 challenge phrase 的绑定。
5. 手势深度、时序和多帧一致性校验。
6. 无障碍替代路径，不能强迫所有人开启摄像头或麦克风。
7. 对不同地区、设备和残障用户的误伤率评估。
